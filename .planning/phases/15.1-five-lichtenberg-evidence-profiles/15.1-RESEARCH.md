## Summary

Phase 15.1 is a content-authoring phase on the school model Phases 13–15 already shipped. All real schools live in one TypeScript array, `realLichtenbergPrimarySchools`, built by `primarySchool()` and parsed by `schoolSchema`. The directory, `/schools/[slug]/` static paths, and compare table all read that array. Tags, `perfilDaEscola`, Fontes, and the Pública / Privada filter already render. This phase adds five records and the smallest factory overrides needed so those records can be private, use portrait grades, and avoid the inference the current ten still use.

None of the five schools exist in the repo, including as stubs. The current ten stay as they are. A thin Perfil with zero tags is a successful school when the sources are thin. That outcome still has to pass `pnpm validate:data`. Do not relax validators, add tag IDs, add fee fields, or add profile UI.

**Primary recommendation:** Append five `primarySchool()` records to `src/content/schools/real/lichtenbergPrimarySchools/index.ts`, using optional factory overrides that default to today’s public / grades 1–6 / inference behavior, and author portrait-plus-website evidence plus a short PT-BR Perfil on each new record only.

### Pattern 1: Factory defaults stay; the five pass overrides

**What:** `primarySchool()` hardcodes `classification: "public"`, `gradesServed: ["1".."6"]`, and infers `afterSchoolCare` from `ganztag` and `schoolProfile` / `pedagogyFocus` from `offers` unless the caller passes those fields `[VERIFIED: lichtenbergPrimarySchools/index.ts lines 158–213]`.
**When to use:** Every new record. The existing ten call sites must not gain new arguments.

Recommended factory change, defaults equal to today so the ten stay byte-stable:

- `classification?: "public" | "private"` default `"public"`.
- `gradesServed?: string[]` default `["1","2","3","4","5","6"]`.
- `portraitDateAccessed?: string` default `spikeFullReviewDate` (`"2026-07-10"`). Pass the real access date for the five. The portrait helper is called inside `primarySchool()` with no date today `[VERIFIED: index.ts lines 135–139]`.
- Do **not** change the inference fallback. On each of the five, always pass `afterSchoolCare`, `schoolProfile`, and `pedagogyFocus`. Omitting them while also passing `ganztag` or `offers` reintroduces the inference D-04 forbids.

`level` stays `"primary"` unless the portrait says the school is mixed-level. `schoolLevelSchema` is only `"primary" | "mixed_with_primary"` `[VERIFIED: schoolClassification/index.ts]`. A mixed school must also set `primarySectionDescription` or `schoolSchema` rejects it `[VERIFIED: school/index.ts lines 107–114]`.

### Pattern 3: Research status for a finished portrait-plus-website pass

**What:** `profile_ready` requires `coverageLevel: "detailed"`, and detailed records require `lastResearched` and `lastSourceChecked` `[VERIFIED: researchMetadata/index.ts lines 22–49]`.
**When to use:** All five, after the D-01/D-02 pass, including schools whose Perfil is thin. The Phase 14 thin pilots stayed `directory_only` because that phase did not re-research facts. These five do. `directory` coverage also shrinks the coverage denominator to 11 fields and would hide the detailed-field gaps `[VERIFIED: school/constants.ts lines 32–60]`.

### Pattern 4: Perfil, tags, and Fontes

**What:** Qualitative content is optional strings and an optional `tags` array on the school object. The factory already passes them through with conditional spreads `[VERIFIED: index.ts lines 240–249]`.
**When to use:** Every new school gets `perfilDaEscola` and `qualitativeLastReviewed`. Tags only when evidence earns them.

Schema gates `[VERIFIED: school/index.ts lines 143–161]`:

- Non-empty `tags` requires `perfilDaEscola`.
- Tags or Perfil requires `qualitativeLastReviewed` (`YYYY-MM-DD`).
- `qualitativeResearchNotes` alone does not require the date.
- No Zod max length on the Perfil.

`validateTagEvidence` derives confidence. The author must set the derived value or the tag is rejected `[VERIFIED: validateTagEvidence/index.ts lines 123–132]`:

- Two or more distinct qualifying source ids → `confirmed_multi_source`.
- Otherwise, if any citation is `official_government`, `official_inspection`, or `school_website` → `confirmed_official`.
- Otherwise → `partial`.
- `active-school-community` needs ≥2 distinct `triangulated_community` source ids, each with `independenceLog`, plus ≥1 non-community allowlisted citation. Any other tag that cites `triangulated_community` or `anecdotal_reserved` is rejected.

Facts-versus-tags, still in force `[VERIFIED: docs/DATA_MODEL.md tag section; docs/EDITORIAL_GUIDE.md “Perfil da Escola Voice”]`: a verified Ganztag string is not `all-day-model`. A language in `languages` is not `languages-focus` or `bilingual-program`. An offers line is not `stem-focus` or `arts-music-focus` by itself. See Grzimek (portrait MINT offer, zero tags) and Wagner (`arts-music-focus` only after a dedicated Musikbetonung page plus the portrait).

Fontes does **not** parse the Perfil. `collectCitedSources` walks `importantSchoolFieldPathsDetailedV2` and `tags[].citations` only `[VERIFIED: collectCitedSources/index.ts lines 44–67]`. A source that exists only in `sources[]` is invisible in Fontes. D-08 is satisfied by putting the checked source ids on the **missing field’s** `evidence.citations`. The `missing()` helper writes `citations: []` `[VERIFIED: index.ts lines 70–76]`. For a checked-but-silent field, do not call `missing()` alone. Build evidence with `status: "missing"`, the source ids, a Portuguese note, and `lastChecked`. Missing fields may carry citations; only `verified` fields are required to have an acceptable factual source `[VERIFIED: school/index.ts lines 79–103; fieldEvidence schema allows citations on every status]`.

Failed community venues (D-12) stay in `qualitativeResearchNotes` and `docs/research/`. Do not cite them on fields or tags, or they will show up in Fontes.

Perfil voice: one short PT-BR paragraph. No ranking. The stock unconfirmed wording already used on the thin pilots is “Até o momento, não houve confirmação independente…” `[VERIFIED: STATE.md Phase 14-05; Seepark/Grzimek/Friedrichsfelder strings in index.ts]`. That sentence means the sources checked do not say so (D-06). It does not say the school lacks the thing.

`EditorialNarrative` renders the string as a React text node, not HTML or MDX `[VERIFIED: EditorialNarrative/index.tsx]`. Keep it plain text.

### Pattern 6: Directory wiring is automatic

**What:** `getRealSchools()` maps the array through `schoolSchema.parse` `[VERIFIED: schoolDirectoryData/index.ts lines 8–11]`. `generateStaticParams` maps those slugs `[VERIFIED: src/app/schools/[slug]/page.tsx lines 8–11]`. `dynamicParams = false`, so an unknown slug 404s at build time.
**When to use:** Always. Adding the record is what publishes `/schools/<slug>/`.

Neighbourhood and language filter options are derived from the data `[VERIFIED: getDirectoryFilterOptions/index.ts]`. A new neighbourhood appears as a checkbox without a UI change. `pedagogyFocus.value` becomes directory `educationalFocus` `[VERIFIED: schoolDirectoryData/index.ts line 40]`. On these five that value must be a direct statement, or the field stays missing and contributes no focus chips.

### Anti-Patterns to Avoid

- **Editing the ten `primarySchool({...})` payloads.** D-17. Factory defaults may change only when omitted arguments reproduce today’s output.
- **Passing `offers` or `ganztag` on a new school without explicit `afterSchoolCare` / `schoolProfile` / `pedagogyFocus`.** The factory will infer `not_confirmed` values and violate D-04.
- **Using `missing()` for a source that was checked and was silent.** Fontes will omit that source.
- **Putting a citation only in the Perfil sentence.** Fontes will not show it, and the editorial rule says the Perfil cannot introduce an uncited claim.
- **Setting confidence by hand to a value other than the derived one.** `validateTagEvidence` rejects the mismatch.
- **Marking Ganztag, a language list, or an offers line as a tag.** Facts-versus-tags.
- **Searching parent forums for every school.** D-09 and D-10. The Tolstoi log is a withhold example, not a search template.
- **Leaving the five as `directory_only` to keep coverage percentages high.** That misstates a finished portrait-plus-website pass and uses the smaller field set.
- **Adding schema, MDX profiles, religious tags, or profile UI.** Out of scope.
- **Changing `tagTaxonomy`’s `toHaveLength(10)`.** That assertion is the closed taxonomy, not the school count `[VERIFIED: tagTaxonomy/index.test.ts line 111]`.

## Common Pitfalls

### Pitfall 1: Factory inference silently violates D-04
**What goes wrong:** After-school care, Perfil oficial, or pedagogy is `not_confirmed` and copied from Ganztag or offers.
**Why it happens:** Those three fields fall back to `inferredFrom()` when omitted `[VERIFIED: index.ts lines 172–213]`.
**How to avoid:** On all five records, pass the three fields explicitly. Verified only with a direct portrait or website statement. Otherwise `missing` with a Portuguese note. Do not pass `offers` at all unless those overrides are also passed.
**Warning signs:** `inferredFrom` appears in a diff hunk for a new school. Coverage shows “Informação inferida, não confirmada” on those fields.

### Pitfall 2: Checked sources never reach Fontes
**What goes wrong:** The Perfil says a point is unconfirmed, but Fontes does not list the page that was checked.
**Why it happens:** `missing()` stores `citations: []`. Perfil text is not a citation source.
**How to avoid:** For each unconfirmed decision-relevant field, cite the portrait and the website page that were read and were silent. Those ids must exist in `sources[]`.
**Warning signs:** `sources.length` is greater than the number of Fontes entries on the rendered profile. `pnpm validate:data` still passes, because orphan sources are legal.

### Pitfall 3: Hardcoded “10” and neighbourhood numerators
**What goes wrong:** Jest or Playwright fails, or a test is “fixed” to the wrong neighbourhood count.
**Why it happens:** Several tests encode today’s 10-school dataset. Karlshorst is 4 and Friedrichsfelde is 6 **before** these five exist. Their neighbourhoods are not in the repo.
**How to avoid:** Change unfiltered totals from 10 to 15. After portraits are read, set Karlshorst and Friedrichsfelde numerators from the finished data. Do not assume the five are outside those neighbourhoods. Do not change the taxonomy length assertion.
**Warning signs:** A patch updates `tagTaxonomy/index.test.ts`, or sets “4 de 15” before neighbourhoods are known.

### Pitfall 4: Dates disagree
**What goes wrong:** `validate:data` fails on `lastSourceChecked` or `qualitativeLastReviewed`.
**Why it happens:** Portrait `dateAccessed` defaults to `2026-07-10` if the factory is not given a date. A September 2026 website cite then requires `lastSourceChecked` >= that website date. An ISO datetime in `qualitativeLastReviewed` fails Zod `.date()`.
**How to avoid:** Pass the real access date into the portrait and every website source. Set `lastResearched` and `lastSourceChecked` to that research day. Set `qualitativeLastReviewed` to `YYYY-MM-DD` of the qualitative writing.
**Warning signs:** Error text `lastSourceChecked (...) must be >= most recent cited source dateAccessed`.

### Pitfall 5: Tag confidence or community rules
**What goes wrong:** A tag that “looks sourced” fails `validateTagEvidence`.
**Why it happens:** Confidence is computed, not chosen. Two website pages are two source ids and derive `confirmed_multi_source` (Wagner’s music page + portrait). One official page derives `confirmed_official`. Community citations on any tag except `active-school-community` are rejected. Community tags without two independence logs and one non-community source are rejected.
**How to avoid:** Add the tag only after the citations exist, then set `confidence` to the derived value. If incidental venues fail the bar, omit the tag. Write the withhold pair only in that case.
**Warning signs:** `Declared confidence ... does not match derived ...` or `cannot cite triangulated_community`.

### Pitfall 6: Private school copied from the public default
**What goes wrong:** Evangelische is Pública, grades 1–6, or a missing inspection is marked `not_applicable` to inflate coverage.
**Why it happens:** Those values are factory defaults. `not_applicable` raises the percentage by leaving the denominator.
**How to avoid:** Override classification and grades from the portrait. Use `not_applicable` only when the workflow says the field does not apply. Use `missing` when it applies and was not found.
**Warning signs:** Directory filter Privada returns zero schools, or the profile shows “Não se aplica” on a field the portrait simply does not mention.

### Pitfall 7: Rewriting the ten while “only” changing the factory
**What goes wrong:** Phase 16 VAL-01 (byte-stable non-pilot coverage) fails, or pilot Perfil text drifts.
**Why it happens:** A default change inside `primarySchool()` changes every caller.
**How to avoid:** New parameters are optional and default to current literals. Diff the ten call sites and confirm they are untouched. Confirm each of the ten still has the same `classification`, `gradesServed`, `research.status`, and `coverageLevel` as before the edit.
**Warning signs:** A diff hunk inside `bernhard-grzimek-schule` or `seepark-grundschule` that is not whitespace.

### Pitfall 8: Evidence-thin treated as a validation exception
**What goes wrong:** A school with a short portrait ships without a Perfil, with a tag quota filler, or with `verified` on a guess.
**Why it happens:** The school is not in the repo, so thickness is unknown until the portrait is read. None of the five can be pre-classified as thin or rich from this codebase `[VERIFIED: name search misses src/ and docs/]`.
**How to avoid:** Sparse-but-honest is the success case (D-05, D-06). Zero tags is valid. `validate:data` stays mandatory. Do not invent tags to prove the taxonomy.
**Warning signs:** A tag whose only evidence is the same offers list that was refused for Grzimek’s MINT line.
